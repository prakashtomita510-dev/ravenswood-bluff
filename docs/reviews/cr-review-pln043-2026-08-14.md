## 2. 原语化等价性逐段对照（审查重点 #1）

对照基准：`git diff src/agents/ai_agent.py`（HEAD `3d8ac2d` → 工作区 `b9428e5`）。

### 2.1 `_decide_local_low_value` ✅ 等价
原内联段与提取后的原语逐行一致：
```python
decision = self._local_low_value_decision(visible_state, legal_context, action_type)
self._record_action_metric(visible_state, action_type, model="local-heuristic",
                           latency_ms=0, fallback_used=False)
return decision
```
`_record_action_metric` 参数（model/latency_ms/fallback_used）完全一致。✅

### 2.2 `_decide_slayer_shot` ✅ 等价
原内联段（`_can_attempt_slayer_shot` → `_select_slayer_shot_target` → `_player_name_from_visible_state` → logger.info → `_record_action_metric("slayer_shot")` → 返回 dict）与提取后的原语逐行一致，仅把嵌套 `if` 改写为等价 early-return。`_record_action_metric` 用 `"slayer_shot"` 字面量而非 `action_type`，与原文一致。✅

### 2.3 `_draft_reuse_decision` ❌ **不等价（P0-1）**

原 act() 内联段（diff 中被删除的 `-` 行）：
```python
if (
    cached_speech_draft
    and action_type in {"speak", "defense_speech"}
    and not refinement_mode          # ← 关键条件
):
```

提取后的原语（第 706-714 行）：
```python
def _draft_reuse_decision(self, visible_state, action_type, cached_speech_draft):
    if not cached_speech_draft or action_type not in {"speak", "defense_speech"}:
        return None
    ...
```

**差异**：原条件中的 `and not refinement_mode` 被**删除**，且原语签名无 `refinement_mode` 参数；act() 调用点（第 644 行）也未传入 `refinement_mode`。而 act() 第 574 行已计算 `refinement_mode = kwargs.get("refinement_mode", False)` 却未使用于草稿判定。

**影响**：`refinement_mode=True`（本轮已有人发言）时，原本应跳过草稿复用、走 `_decide_via_llm` 基于最新局势精炼草稿（原注释第 640-642 行明确此语义），现在直接复用草稿返回 `cache_finalized_draft_reuse`。**这是默认路径（开关 off）的行为变更**，违反 D019「纯提取、行为零变更」承诺。

**证据链**：`tests/test_orchestrator/test_game_loop.py:919-927` 仅断言 orchestrator 传入的 `speak_kwargs["refinement_mode"]` 值，未断言「refinement_mode=True 时 agent 内部是否精炼」，故该回归未被 696 测试捕获。

**修复建议**：`_draft_reuse_decision` 增加 `refinement_mode: bool = False` 参数，恢复 `and not refinement_mode` 判断；act() 调用点传入 `refinement_mode`。工作流 `_decide` 节点调用时同理需从 `ctx` 传递 `refinement_mode`。

### 2.4 `_decide_via_llm` ✅ 等价
主路径核心（记忆检索 / 三层前缀 prompt / tool calling / JSON fallback / 草稿兜底 / 超时兜底）逐行一致，仅把 `refinement_mode` 与 `cached_speech_draft` 的读取提前到函数开头（语义等价），并删除了若干纯注释行（不影响行为）。`_record_action_metric` 参数、`_append_player_thought_log`、`data_collector.record_thought_trace` 调用均与原文一致。✅

## 3. 问题清单

### 🔴 P0-1（阻断提交）— `_draft_reuse_decision` 丢失 `not refinement_mode`

- **文件/行号**：`src/agents/ai_agent.py:706-714`（原语定义）、`:644`（调用点未传 refinement_mode）
- **根因**：草稿复用条件提取时丢失 `and not refinement_mode`，违反「原语化逐行等价」红线。
- **影响**：refinement_mode=True 时错误复用草稿（默认路径行为变更），发言不再基于最新局势精炼。
- **修复建议**：原语签名加 `refinement_mode` 参数并恢复判断；act() 与工作流 `_decide` 节点均正确传递。

### 🟡 P1-2 — 工作流 `_decide` 漏掉 speak/nomination_intent 的猎手主动开枪判定

- **文件/行号**：`src/agents/workflow/action_workflows.py:80-96`
- **根因**：act() 原路径对**所有** action_type 先过 `_decide_slayer_shot`（内部 `can_attempt_slayer_shot` 要求 `action_type in {"speak","nomination_intent"}` + 猎手 + `can_slayer_shot`）。工作流用 `elif action_type == "slayer_shot"` 分支，但 orchestrator 从不以 `"slayer_shot"` 作为 action_type 调 `act()`（slayer_shot 是决策**返回值**，见 `day_discussion.py:166` / `nomination_voting.py:72`），故该分支为死代码；speak/nomination_intent 走 `else` 分支跳过猎手判定。
- **影响**：开关 on 时，猎手在白天讨论/提名意图时丧失本地主动开枪能力（只能依赖 LLM 偶然返回 slayer_shot）。
- **修复建议**：`_decide` 节点在 local/slayer 判定顺序上对齐 act()：先对 speak/nomination_intent 调 `_decide_slayer_shot`（返回非 None 即用），再走 local/draft/llm。

### 🟡 P1-3 — recall 节点注入的观点摘要未传给 decide 的 LLM 路径

- **文件/行号**：`src/agents/workflow/action_workflows.py:61-72`（recall 写 `ctx["strategic_thought"]`）、`:94-96`（decide 只传 `ctx["llm_kwargs"]`）
- **根因**：`_recall` 把 `store.build_summary()` 摘要写入 `ctx["strategic_thought"]`，但 `_decide` 调 `_decide_via_llm(..., **ctx.get("llm_kwargs", {}))` 未合并该字段；`_decide_via_llm` 内部读 `kwargs.get("strategic_thought")`，收不到 recall 注入的摘要。
- **影响**：观点摘要（认知闭环产出）实际未进入 LLM 决策 prompt，recall 节点设计意图失效。
- **修复建议**：`_decide` 调用 `_decide_via_llm` 前把 `ctx.get("strategic_thought")` 合并进 `llm_kwargs`。

### 🟡 P1-4 — `_feedback_decision_to_viewpoints` 证据未匹配观点主题

- **文件/行号**：`src/agents/workflow/action_workflows.py:172-185`
- **根因**：有激活观点时，对**每个** `active` 观点都用同一批 `new_evidence`（`for _ in candidates` 仅把同一 reasoning 重复 `len(candidates)` 次）更新，不检查 `vp.subject_name` 是否属于 `candidates`。导致所有激活观点（无论主题）被同一决策盲目提升置信度；且 `superseded` 分支为死代码（`update_with_new_evidence` 的冲突检测只针对 `new_hard`，而此处证据全为 soft）。
- **影响**：观点置信度被不相关证据虚增，演化闭环语义错误；测试 `test_record_feedback_updates_viewpoint` 因只预置单观点且恰好匹配，未暴露错配。
- **修复建议**：仅对 `vp.subject_name in candidates` 的观点更新；证据按 subject 一一匹配，避免重复计数。

### 🟡 P1-5 — `test_workflow_declares_four_nodes` 污染 BOTC_DATA_DIR 且未撤销

- **文件/行号**：`tests/test_agents/test_action_workflows.py:95-100`
- **根因**：`_make_agent(Path("."), __import__("pytest").MonkeyPatch())` 用**独立** MonkeyPatch 实例（非 pytest fixture，不自动撤销），且 `tmp_path="."` → `setenv("BOTC_DATA_DIR", ".")`。测试结束后 `os.environ["BOTC_DATA_DIR"]="."` 残留，同一 pytest 进程内后续**未显式 setenv** 的测试据此写到仓库根目录。
- **影响**：本次验收实测全量测试后根目录产生 `agents/`、`storyteller/`（含 `fixed-game-id-1`、`wf-night-test` 等测试产物，已清理）。`test_action_workflows.py` 在 `tests/test_agents/` 中字母序最前，污染影响面最大。
- **修复建议**：改用 pytest 的 `tmp_path`/`monkeypatch` fixture，或 `with MonkeyPatch.context()` 上下文管理器；不要用 `Path(".")` 作数据目录。

### 🔵 P2-6 — 玩家名提取硬编码 "P1"~"P10"

- **文件/行号**：`src/agents/workflow/action_workflows.py:164-166`
- **根因**：`for name in ("P1",...,"P10")` 硬编码，与真实玩家名 `"Player {seat}"`（`game_loop.py:198`）不匹配；仅当 reasoning 用 `p1`/`P1`（player_id 风格）时才能命中（`name.lower() in reasoning.lower()`）。
- **影响**：真实对局若 reasoning 用 "Player 1" 则无法创建观点；命名对 player_count>10 不健壮。
- **修复建议**：从 `visible_state` 提取真实 `player_id`/`name` 做匹配。

### 🔵 P2-7 — 无激活观点分支仅取 candidates[0]

- **文件/行号**：`src/agents/workflow/action_workflows.py:187`
- **根因**：`name = candidates[0]` 只创建第一个候选的观点，丢弃其余候选玩家。
- **影响**：单次决策提到多名玩家时仅记录一条观点。
- **修复建议**：为去重后的每个候选创建观点（或至少记录全部）。
